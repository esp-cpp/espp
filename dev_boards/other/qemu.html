QEMU (emulator)#

QEMU#

The espp::Qemu component is a board-support package for Espressif’s QEMU: not a board, but the few virtual peripherals the emulator offers, wrapped with the same shape as the real-board BSPs so an espp application runs with no hardware at all. It builds for the three targets the emulator supports (esp32, esp32c3, esp32s3).

  • Display: the virtual RGB panel as an LVGL display (initialize_display()). What LVGL draws appears in the QEMU window, or off screen in a headless run (SDL_VIDEODRIVER=dummy), and can be captured with the QEMU monitor’s screendump. The display needs a display backend: with -display none the panel driver’s first flush waits forever.

  • Ethernet: the OpenCores Ethernet MAC (initialize_ethernet()), a real lwIP interface on QEMU’s user-mode NAT or on a tap device. Needs CONFIG_ETH_USE_OPENETH.

  • SD card (ESP32 machine only): the SD/MMC host (initialize_sdcard()), a FAT volume on the image file passed with -drive file=...,if=sd.

Everything else (touch, I2C, I2S, Wi-Fi, BLE, USB) is not emulated. See Running espp in QEMU for installing the emulator, headless runs, screenshots, networking and debugging.

class Qemu : public espp::BaseComponent#

Board-support package for Espressif’s QEMU emulator.

QEMU is not a board, but it has a few virtual peripherals that no real board has, and an application that targets them runs with no hardware at all: on a developer’s machine, in CI, or in a container. This BSP wraps the ones the emulator offers, with the same shape as the real-board BSPs:

  • the virtual RGB panel, as an LVGL display (`initialize_display()`): what LVGL draws appears in the QEMU window (`-display sdl` / `idf.py qemu &#8212;graphics`) and can be captured with the QEMU monitor’s `screendump`;

  • the OpenCores Ethernet MAC (`initialize_ethernet()`): a real lwIP interface on QEMU’s user-mode NAT (`-nic user,model=open_eth`, the default of `idf.py qemu`) or on a tap device;

  • the SD/MMC host (`initialize_sdcard()`, ESP32 only): a FAT volume on an image file passed with `-drive file=sd.img,if=sd,format=raw`.

Everything else (touch, I2C, I2S, Wi-Fi, BLE, USB) is not emulated. The component builds for the three targets the emulator supports (esp32, esp32c3, esp32s3); see the component README for the QEMU command lines.

QEMU Example#

  auto &qemu = espp::Qemu::get();

  // The virtual RGB panel: appears as the QEMU window with --graphics /
  // -display sdl, and renders headless otherwise (screendump works either
  // way). Nothing to do with real hardware: initialize_display() fails there.
  logger.info("Initializing display...");
  if (!qemu.initialize_display({.width = 320, .height = 240})) {
    logger.error("Failed to initialize the display (not running in QEMU?)");
    return;
  }

  // the UI: status lines + a sweeping arc, updated from here and from the
  // Ethernet callbacks
  Gui gui({.log_level = espp::Logger::Verbosity::WARN});

  // The OpenCores Ethernet MAC on QEMU's user-mode network: a DHCP client
  // gets 10.0.2.15 from QEMU, with 10.0.2.2 as the gateway (the host) and
  // 10.0.2.3 as the DNS server.
  logger.info("Initializing Ethernet...");
  bool eth_ok = qemu.initialize_ethernet({
      .mode = espp::Qemu::DhcpMode::CLIENT,
      .on_link_up = [&]() { gui.set_ethernet_text("Ethernet: link up, waiting for DHCP"); },
      .on_link_down = [&]() { gui.set_ethernet_text("Ethernet: link down"); },
      .on_got_ip =
          [&](esp_ip4_addr_t ip) {
            std::string text = "Ethernet: " + std::to_string(esp_ip4_addr1(&ip)) + "." +
                               std::to_string(esp_ip4_addr2(&ip)) + "." +
                               std::to_string(esp_ip4_addr3(&ip)) + "." +
                               std::to_string(esp_ip4_addr4(&ip));
            logger.info("{}", text);
            gui.set_ethernet_text(text);
          },
  });
  if (!eth_ok) {
    logger.error("Failed to initialize Ethernet");
    gui.set_ethernet_text("Ethernet: failed (CONFIG_ETH_USE_OPENETH?)");
  }

#if CONFIG_IDF_TARGET_ESP32
  // The SD card image attached with -drive file=sd.img,if=sd,format=raw.
  // QEMU emulates the SD/MMC host on the ESP32 machine only (the ESP32-S3 has
  // the peripheral in silicon, but not in the emulator), so the other targets
  // skip this.
  logger.info("Initializing SD card...");
  if (qemu.initialize_sdcard({.mount_point = "/sdcard"})) {
    const char *path = "/sdcard/hello.txt";
    std::string status = "SD card: mounted";
    if (FILE *f = fopen(path, "w"); f != nullptr) {
      fprintf(f, "hello from espp in QEMU, boot %lld us\n", esp_timer_get_time());
      fclose(f);
      char line[80] = {};
      if (FILE *r = fopen(path, "r"); r != nullptr) {
        if (fgets(line, sizeof(line), r) != nullptr) {
          logger.info("Read back from {}: {}", path, line);
          status = "SD card: hello.txt written and read back";
        }
        fclose(r);
      }
    } else {
      status = "SD card: mounted, but could not write hello.txt";
    }
    gui.set_sdcard_text(status);
  } else {
    logger.warn("No SD card (attach an image with -drive file=sd.img,if=sd,format=raw)");
    gui.set_sdcard_text("SD card: none (see README)");
  }
#else
  gui.set_sdcard_text("SD card: not emulated on this target");
#endif // CONFIG_IDF_TARGET_ESP32

  // Keep the uptime line and a heap figure moving, so a log capture or a
  // screenshot taken at any time shows a live system.
  int seconds = 0;
  while (true) {
    std::this_thread::sleep_for(1s);
    seconds++;
    gui.set_uptime_text("Uptime: " + std::to_string(seconds) + " s");
    if (seconds % 10 == 0) {
      logger.info("Uptime {} s, free heap {} bytes, Ethernet {}", seconds,
                  heap_caps_get_free_size(MALLOC_CAP_DEFAULT),
                  qemu.is_ethernet_connected() ? "up" : "down");
    }
  }

struct DisplayConfig#

Configuration for the virtual RGB panel + LVGL display.

Public Members

size_t width = {320}#

Panel (QEMU window) width in pixels.

size_t height = {240}#

Panel (QEMU window) height in pixels

size_t pixel_buffer_size = {0}#

Size of each LVGL draw buffer, in pixels (two of them with double_buffered, else one); 0 = a tenth of the panel. The panel has its own frame buffer, in QEMU-side memory, that draw_bitmap() copies into; LVGL renders into these internal-RAM draw buffers.

bool double_buffered = {true}#

Two draw buffers (render one while the other is flushed).
