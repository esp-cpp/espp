Audio#

The espp::Audio component drives one I2S port with 16-bit PCM: a TX channel for playback, an RX channel for recording, or both, full duplex, in standard (Philips) mode. An instance that only records can instead receive TDM (e.g. an ES7210 with four microphones) or a PDM microphone, and HardwareConfig::recording_slots picks the slots its callback receives. It owns the machinery the espp BSPs used to copy into each board:

  • the I2S channels and their DMA rings, sized so the TX ring outlasts the playback task’s bounded wait,

  • the playback stream buffer and task, which always writes whole blocks so the TX ring never runs dry (no pops between sounds),

  • the recording task, which drains the RX ring continuously and hands the samples to a callback while recording,

  • volume, mute and microphone gain (in the codec, or volume and mute in software when there is no codec),

  • sample rate changes, and

  • a complete unwind when initialization fails, deinitialize() and the destructor.

Chip-specific setup goes through the espp::AudioCodec interface. This component provides adapters for the ES8311 (espp::Es8311Codec, playback and recording), the ES8388 (espp::Es8388Codec, playback) and the ES7210 (espp::Es7210Codec, recording), on the drivers in the codec component. A chip that handles both directions, like the ES8311, is passed as both the output and the input codec.

espp::Audio::Config has two parts: an espp::Audio::AppConfig (what an application chooses: the sample rate, which directions run, the playback buffer and the tasks) and an espp::Audio::HardwareConfig (how the board is wired: the I2S port and pins, channels, the recording format and slots, the MCLK multiple and the codecs). The BSPs take only the AppConfig, as their AudioConfig, and fill in the HardwareConfig for their board.

Board-specific parts - amplifier enable pins, IO expanders, buttons - stay in the BSP. Config::on_playback_block lets a BSP follow playback activity (the M5Stack Tab5 pauses its battery charger with it, since the charger pops the speaker). A board whose microphones are on a separate I2S port uses two instances: one for playback and one for recording, which such a BSP’s microphone_audio() returns.

BSP audio API#

The BSPs that use this component expose the same audio methods, which forward to it: initialize_audio() / initialize_audio(const AudioConfig &) (AudioConfig is espp::Audio::AppConfig; default_audio_config() returns the board’s defaults to start one from), deinitialize_audio(), is_audio_initialized(), audio(), enable_audio(bool) (the amplifier), play_audio(std::span<const uint8_t>) / play_audio(const uint8_t *, size_t), clear_audio(), volume(), mute() / is_muted(), audio_sample_rate(), audio_buffer_size(), start_audio_recording(callback) / stop_audio_recording() and microphone_volume(). Older names are kept as [[deprecated]] methods that forward to these.

class Audio : public espp::BaseComponent#

I2S audio playback and recording, shared by the espp BSPs.

One instance drives one I2S port in standard (Philips) mode with 16-bit PCM: a TX channel for playback, an RX channel for recording, or both, full duplex on the same clocks. It owns all of the machinery that used to be copied into each BSP:

  • the I2S channels and their DMA rings, sized so the ring outlasts the playback task’s bounded wait (i2s_tx_feed.hpp),

  • the playback stream buffer and task, which always writes whole blocks so the TX ring never runs dry,

  • the recording task, which drains the RX ring continuously and hands the samples to a callback while recording,

  • volume / mute (in the codec, or in software when it has none) and microphone gain,

  • sample rate changes, and

  • a complete unwind on failure, deinitialize() and the destructor.

Chip-specific configuration goes through espp::AudioCodec (see the ES8388 / ES7210 adapters in this component). Board-specific parts - amplifier enable pins, IO expanders, buttons - stay in the BSP; Config::on_playback_block lets a BSP follow playback activity (the M5Stack Tab5 pauses its charger with it).

A board whose microphones are on a separate I2S port uses two instances: one for playback and one for recording.

Example#

  // Playback only, to an I2S amplifier with no codec (e.g. a MAX98357A):
  // volume and mute are applied in software.
  espp::Audio audio({
      .app = {.sample_rate = 44100, .playback_enabled = true, .recording_enabled = false},
      .hardware = {.pins = {.bclk = static_cast<gpio_num_t>(CONFIG_EXAMPLE_I2S_BCLK_GPIO),
                            .ws = static_cast<gpio_num_t>(CONFIG_EXAMPLE_I2S_WS_GPIO),
                            .dout = static_cast<gpio_num_t>(CONFIG_EXAMPLE_I2S_DOUT_GPIO)}},
      .volume = 30.0f,
      .log_level = espp::Logger::Verbosity::INFO,
  });
  if (!audio.initialize()) {
    logger.error("Could not initialize the audio");
    return;
  }

  // One second of a 440 Hz tone, 16-bit interleaved stereo
  const uint32_t rate = audio.sample_rate();
  std::vector<int16_t> tone(rate * 2);
  for (size_t i = 0; i < rate; i++) {
    const float t = static_cast<float>(i) / rate;
    const auto sample =
        static_cast<int16_t>(std::sin(2.0f * std::numbers::pi_v<float> * 440.0f * t) * 8000.0f);
    tone[2 * i] = sample;
    tone[2 * i + 1] = sample;
  }
  std::span<const uint8_t> bytes(reinterpret_cast<const uint8_t *>(tone.data()),
                                 tone.size() * sizeof(int16_t));

  // play() queues what fits and returns how much that was: stream the tone in
  // from the returned offset
  auto play_all = [&](std::span<const uint8_t> data) {
    while (!data.empty()) {
      const size_t queued = audio.play(data);
      data = data.subspan(queued);
      if (queued == 0) {
        std::this_thread::sleep_for(5ms);
      }
    }
  };

  for (float volume : {30.0f, 60.0f, 90.0f}) {
    logger.info("Playing the tone at {:.0f} % volume", volume);
    audio.volume(volume);
    play_all(bytes);
    std::this_thread::sleep_for(500ms);
  }
  logger.info("Playing the tone muted");
  audio.mute(true);
  play_all(bytes);
  // play_all() returns once the tone is queued (the stream and the DMA ring
  // still hold about 130 ms): let that play out muted before unmuting
  std::this_thread::sleep_for(250ms);
  audio.mute(false);

  // the audio is torn down when `audio` goes out of scope; deinitialize() does
  // it explicitly
  std::this_thread::sleep_for(1s);
  audio.deinitialize();

Public Types

enum class RecordingFormat#

How the recording (RX) channel receives.

Values:

enumerator STANDARD#

Standard (Philips) I2S: two slots per frame. In full duplex it runs on the playback clocks.

enumerator TDM#

TDM: HardwareConfig::recording_tdm_slots slots per frame (e.g. an ES7210 with four microphones). Recording only; needs SOC_I2S_SUPPORTS_TDM.

enumerator PDM#

A PDM microphone: Pins::ws is its clock and Pins::din its data; mono. Recording only; needs SOC_I2S_SUPPORTS_PDM_RX.

using recording_callback_t = std::function<void(const uint8_t *data, size_t length)>#

Function called with recorded audio: 16-bit signed PCM, interleaved when HardwareConfig::recording_channels is 2. Runs on the recording task; it may call any method except start_recording() (which fails from it: it waits for the callback to return), initialize() and deinitialize().

using playback_block_callback_t = std::function<void(bool active)>#

Function called by the playback task once per block with whether the block carried audio (false: silence). Keep it short and non-blocking; it must not call initialize() or deinitialize().

struct AppConfig#

What an application chooses: the rate, which directions run, buffering and the tasks. The BSPs take this (as their AudioConfig) and fill in the HardwareConfig for their board.

Public Members

uint32_t sample_rate = {48000}#

Sample rate, in Hz (at least UPDATE_FREQUENCY).

uint32_t recording_sample_rate = {0}#

The recording rate, in Hz, for an instance that only records (0: sample_rate). An instance that plays and records runs both on one clock, so it must be 0 or sample_rate there; a playback-only instance ignores it. Lets a board whose microphones have their own I2S port (e.g. the T-Deck) record at a rate other than it plays.

bool playback_enabled = {true}#

Set up playback (the TX channel, the output codec and the playback task).

bool recording_enabled = {false}#

Set up recording (the RX channel, the input codec and the recording task).

Note

Each I2S channel has a DMA ring in internal DMA-capable RAM (about 11.5 KB of stereo frames up to 48 kHz; half that for an instance that only records, times the slots / 2 for TDM) and each task a stack in internal RAM, so a direction that is not needed is better left off.

size_t playback_buffer_size = {0}#

Size of the playback stream that play() queues into, in bytes (0: four blocks, about 67 ms). Larger lets one play() queue a whole UI sound; at least two blocks.

uint32_t playback_buffer_caps = {MALLOC_CAP_INTERNAL | MALLOC_CAP_8BIT}#

Heap capabilities for the playback stream (e.g. MALLOC_CAP_SPIRAM for a large one).

Recording channels: 2 (interleaved stereo) or 1 (mono); other values are rejected. They are taken from recording_slots (by default mono is the left slot).

Note

Mono is received as stereo slots and the callback gets the left slot only: an RX channel in mono slot mode still delivers both slots (measured on the ESP32-P4, recording only and full duplex: twice the samples, in a DMA ring sized for one). So mono costs a stereo RX DMA ring.

RecordingFormat recording_format = {RecordingFormat::STANDARD}#

How the RX channel receives (STANDARD, TDM or PDM). TDM and PDM are for an instance that only records (playback_enabled = false), e.g. a board whose microphones have their own I2S port.

uint8_t recording_tdm_slots = {4}#

TDM: slots per frame, 2 - 16.

std::array<uint8_t, 2> recording_slots = {0, 1}#

The slots the callback receives, in order: the first recording_channels (1 or 2) of them (STANDARD: of 2, TDM: of recording_tdm_slots; PDM has one). E.g. {0, 2} keeps a four-slot ES7210’s MIC1 and MIC3 as stereo, and {1} with one channel the right slot as mono.

i2s_mclk_multiple_t mclk_multiple = {I2S_MCLK_MULTIPLE_256}#

MCLK as a multiple of the sample rate.

std::shared_ptr<AudioCodec> output_codec = {}#

The codec for playback (nullptr: none, e.g. an I2S amplifier; volume and mute are then applied in software).

std::shared_ptr<AudioCodec> input_codec = {}#

The codec for recording (nullptr: none, e.g. an I2S microphone). May be the same object as output_codec.

class AudioCodec#

Interface between espp::Audio and an audio codec chip.

espp::Audio owns the I2S channels, the playback and recording tasks and the stream buffer; a codec only has to configure its chip. espp::Audio calls these methods from initialize(), deinitialize() and its setters - never per sample or per block - so the virtual dispatch costs nothing measurable.

A chip that handles both directions (e.g. an ES8311) is passed as both the output and the input codec of espp::Audio::Config; it is then started once, with Direction::BOTH.

The I2S clocks (MCLK, BCLK, WS) are running when start() is called, since most codecs need MCLK to accept their register writes.

Subclassed by espp::Es7210Codec, espp::Es8311Codec, espp::Es8388Codec

class Es8311Codec : public espp::AudioCodec#

espp::AudioCodec for the ES8311 mono codec (DAC and ADC), on the codec component’s ES8311 driver.

Configures the ES8311 as an I2S slave for 16-bit Philips data at the I2S sample rate (its clock coefficients follow set_sample_rate() too), drives its hardware volume and mute and maps a 0 - 100 % microphone gain onto its analog gain steps (0 dB - 42 dB). It handles both directions, so pass the same instance as espp::Audio::HardwareConfig::output_codec and input_codec; its ADC drives the left slot (use recording_channels = 1).

Note

The codec component’s ES8311 driver keeps its register access functions in globals, so there can be only one ES8311 per firmware. This class sets them when it is constructed.

Note

It logs through ESP_LOGx (tag “Es8311Codec”) rather than an espp::Logger, whose mutex would cost internal RAM for the few messages an init failure prints.
