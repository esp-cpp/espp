Persistent Data APIs

Persistent Data

The PersistentData class stores one data structure (a settings struct, calibration data, a paired-device list) in a file on any filesystem reachable through the VFS, tracks the schema version of what is on disk in a small header (magic, version, a portable layout fingerprint, length, CRC32) and migrates older files forward through a chain of migrate() steps when the structure changes. Saves are atomic (temporary file plus rename), every operation reports a std::error_code (PersistentDataErrc), and encode() / decode() expose the same bytes for other storage backends.

Code examples for the Persistent Data API are provided in the persistent_data example folder.

Classes

template<persistent_data::VersionedType... Versions>
class PersistentData : public espp::BaseComponent

File-backed storage for one data structure with schema versioning and forward migration.

Stores a serializable aggregate (see the serialization component) in a single file on any filesystem reachable through the VFS (LittleFS, SPIFFS, SD card). Every file carries a small header with a magic number, the schema version of the data it holds, a portable fingerprint of the type’s layout, the payload length and a CRC32, so a load distinguishes “no file yet”, “corrupt or truncated”, “written by newer firmware”, “version number reused for a different

layout” and “old version, migrated” instead of guessing by trying to parse. The format is identical on every target and on the host, so a PC tool can read and write a device’s file.

Versions are given as a type list, newest first; the first type is the current one. Each type declares `static constexpr uint32_t VERSION` (strictly decreasing along the list) and every type except the last provides `static T migrate(const Older &)` from the type after it. A file of an older version is decoded as that version and walked toward the front of the list one step at a time, so each version only knows how to come from the one before it. A new version is prepended; dropping support for the oldest version is removing the last entry: such files then load with PersistentDataErrc::unknown_version and the application decides what to do (typically load_or_create()).

Saves are atomic: the data is written to `<file>.tmp`, synced, then renamed over the file, so a reset mid-save keeps the previous contents.

All methods are thread-safe; get() returns a copy and update() runs the caller’s function and the save under the same lock. A save blocks other callers for the duration of the flash write. For convenience the object converts to a copy of the data (get()) and can be assigned from it (set()); saving stays an explicit call because it can fail.

Persistent Data Example

    // The type list is newest first; the first type is the current one. A file
    // written by any listed version loads and is migrated to Settings.
    using PersistentSettings = espp::PersistentData<Settings, SettingsV2, SettingsV1>;
    std::error_code ec;
    PersistentSettings settings({
        .file_path = settings_path,
        .auto_load = false, // we want to handle "no file yet" ourselves below
        .log_level = espp::Logger::Verbosity::INFO,
    });

    // load the file, or create it from defaults if there is none; any other
    // error (corrupt file, newer firmware's file) is reported, not papered over
    if (!settings.load_or_create(Settings{}, ec)) {
      logger.error("Could not load or create settings: {}", ec.message());
    }
    logger.info("Loaded (file version {}): {}", settings.loaded_version(), settings.get());

    // read-modify-write under one lock, saved atomically
    settings.update([](Settings &s) { s.boot_count++; }, ec);
    if (ec) {
      logger.error("Could not save settings: {}", ec.message());
    }

    // get() returns a copy; set() only changes memory, save() writes it
    auto copy = settings.get();
    copy.favorites = {"red", "green"};
    settings.set(copy);
    settings.save(ec);

    // the same through the conversion / assignment operators
    Settings s = settings; // == settings.get()
    s.display.brightness = 1.0f;
    settings = s; // == settings.set(s)
    settings.save(ec);

Migration Example

    // Write a version-1 file the way the first firmware would have, then load
    // it with the full version list: it comes back migrated v1 -> v2 -> v3 and
    // (save_after_migration, the default) the file is rewritten as version 3.
    {
      espp::PersistentData<SettingsV1> old_firmware(
          {.file_path = settings_path, .auto_load = false});
      old_firmware.save(SettingsV1{.brightness = 80, .device_name = "legacy"}, ec);
      check("v1 file written", !ec);

      PersistentSettings settings({.file_path = settings_path});
      check("v1 file loads", settings.is_loaded() && settings.loaded_version() == 1);
      check("v1 file was migrated", settings.was_migrated());
      auto s = settings.get();
      check("migration kept the name", s.device_name == "legacy");
      check("migration converted brightness 80 -> 0.80", s.display.brightness == 0.80f);
      check("migration filled v2 defaults", s.display.color_rgb == 0x00FF00 && s.favorites.empty());
      check("migration filled v3 defaults", s.boot_count == 0);

      PersistentSettings again({.file_path = settings_path});
      check("file was rewritten as the current version",
            again.loaded_version() == PersistentSettings::CURRENT_VERSION && !again.was_migrated());
    }
