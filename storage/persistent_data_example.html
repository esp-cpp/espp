Persistent Data Example

This example shows how the persistent_data component stores a settings structure in a file on a littlefs partition, how the structure evolves over firmware versions (a version-1 file written by old firmware is migrated v1 -> v2 -> v3 and rewritten), and how corrupt, truncated and newer-firmware files are reported instead of guessed at.

The example ends with a validation section that exercises every operation (create, auto-load, update(), migration, newer-version refusal, corruption detection, encode() / decode()) and prints a pass / fail summary.

How to use example

Hardware Required

Any ESP32 with a littlefs partition (see partitions.csv); the partition label is configured through menuconfig (CONFIG_ESPP_FILE_SYSTEM_PARTITION_LABEL).

Build and Flash

Build the project and flash it to the board, then run monitor tool to view serial output:

idf.py -p PORT flash monitor

(Replace PORT with the name of the serial port to use.)

(To exit the serial monitor, type Ctrl-].)

See the Getting Started Guide for full steps to configure and use ESP-IDF to build projects.
